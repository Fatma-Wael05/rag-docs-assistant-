# RAG Docs Assistant

A Retrieval-Augmented Generation (RAG) system that answers questions about AI agent frameworks — **LangChain**, **LangGraph**, **CrewAI**, and **LlamaIndex** — grounded in their real, official documentation. Runs fully locally via [Ollama](https://ollama.com); no API keys required.

The pipeline: a corpus-building script clones the actual doc repos and cleans them into plain markdown, a notebook chunks and embeds that corpus into a local Chroma vector store, a FastAPI backend retrieves relevant chunks and generates a cited answer via Ollama, and a Streamlit frontend provides a chat interface.

## Architecture

```
build_corpus.py                 rag_pipeline_unexecuted.ipynb
     │                                    │
     ▼                                    ▼
_doc_repos/ (cloned repos)   data/raw/*.md → chunk → embed
     │                                    │
     ▼                                    ▼
data/raw/*.md ─────────────────►  data/vector_store/  (Chroma, local)
                                           │
                                (copy into backend/data/vector_store/)
                                           │
                                           ▼
                              backend/  (FastAPI + Ollama)
                                  GET  /health
                                  POST /query
                                           │
                                           ▼
                              frontend/  (Streamlit chat UI)
```

**Why the copy step:** the notebook persists the vector store to `data/vector_store` (relative to the project root, where you run Jupyter). The backend reads from `backend/data/vector_store` (relative to where `uvicorn` runs). These are two different folders on purpose — the notebook is a standalone data-prep step, and the backend only needs the final built store — so you copy the output over once after building it. See Step 4 below.

## Prerequisites

- Python 3.10+
- Git
- [Ollama](https://ollama.com) installed and running locally

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/Fatma-Wael05/rag-docs-assistant-.git
cd rag-docs-assistant-
```

### 2. Create a virtual environment

```bash
python -m venv venv
# Windows:
.\venv\Scripts\Activate.ps1
# macOS/Linux:
source venv/bin/activate
```

### 3. Pull the Ollama model

```bash
ollama pull llama3.1
```

Make sure Ollama is running in the background (it usually starts automatically after install; otherwise run `ollama serve` in a separate terminal).

### 4. Build the corpus and vector store

```bash
python build_corpus.py
```

This shallow-clones the LangChain, CrewAI, and LlamaIndex documentation repos into `_doc_repos/` and writes cleaned markdown into `data/raw/`. Both are gitignored and regenerated fresh each time.

Then run the notebook top to bottom:

```bash
pip install jupyter pandas numpy chromadb sentence-transformers pypdf ollama python-dotenv
jupyter notebook rag_pipeline_unexecuted.ipynb
```

In Jupyter: **Kernel → Restart & Run All**. This chunks and embeds the corpus and persists it to `data/vector_store/`.

**Then copy the built store into the backend's expected location:**

```bash
# Windows PowerShell:
Copy-Item -Recurse -Force data/vector_store backend/data/vector_store
# macOS/Linux:
cp -r data/vector_store backend/data/vector_store
```

### 5. Configure and run the backend

```bash
cd backend
cp .env.example .env
pip install -r requirements.txt
uvicorn app.main:app --reload
```

The API is now live at `http://localhost:8000`, with interactive docs at `http://localhost:8000/docs`.

### 6. Configure and run the frontend

In a separate terminal:

```bash
cd frontend
```

Create a `.env` file (this is gitignored, so it isn't in the repo) containing:

```
API_BASE_URL=http://localhost:8000
```

Then:

```bash
pip install -r requirements.txt
streamlit run app.py
```

The chat UI opens automatically at `http://localhost:8501`.

## Environment Variables

### `backend/.env`

| Variable | Description | Default |
|---|---|---|
| `VECTOR_STORE_DIR` | Path to the persisted Chroma store, relative to where `uvicorn` is run | `data/vector_store` |
| `CHROMA_COLLECTION_NAME` | Name of the Chroma collection to query | `rag_docs` |
| `EMBEDDING_MODEL_NAME` | Sentence-transformers model — must match the one used in the notebook | `all-MiniLM-L6-v2` |
| `OLLAMA_MODEL` | Local Ollama model used for answer generation | `llama3.1` |
| `RETRIEVAL_TOP_K` | Number of chunks retrieved per query | `4` |
| `CORS_ORIGINS` | Comma-separated list of allowed frontend origins | `http://localhost:8501` |

### `frontend/.env`

| Variable | Description | Default |
|---|---|---|
| `API_BASE_URL` | Base URL of the backend API | `http://localhost:8000` |

## API Reference

### `GET /health`

Returns backend and vector store status.

```bash
curl http://localhost:8000/health
```

### `POST /query`

Retrieves relevant chunks and generates a grounded, cited answer.

**Request body:**

```json
{
  "question": "How do I create an agent in CrewAI?"
}
```

**curl example:**

```bash
curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"question": "How do I create an agent in CrewAI?"}'
```

**Response shape:**

```json
{
  "answer": "You can create an agent in CrewAI in two ways: ...",
  "sources": ["crewai_agents.md", "crewai_agents.md", "crewai_agents.md", "crewai_tools.md"],
  "retrieved_chunk_ids": ["crewai_agents.md::10", "crewai_agents.md::0", "crewai_agents.md::15", "crewai_tools.md::3"]
}
```

## Evaluation Results

`data/eval_results.json` contains full transcripts (question, generated answer, retrieved sources, and chunk IDs) for 13 manually reviewed test questions covering all four frameworks. This was a manual qualitative review, not an automated scored benchmark — there is no aggregate accuracy percentage.

| Outcome | Count | Notes |
|---|---|---|
| **Correctly grounded & cited** | 9 / 13 | Answers matched the retrieved source content, with accurate citations. Includes a correct refusal on an out-of-scope question (fine-tuning with HuggingFace Trainer — not in the corpus), which is a good sign the model isn't just answering from its own training knowledge. |
| **Hallucinated detail despite real citations** | 1 / 13 | The "How do I create an agent in CrewAI?" answer invents a nonexistent "JSONC project configuration" format. The citations point to real doc chunks, but the model added a detail that isn't actually in them — a generation-faithfulness issue rather than a retrieval failure. |
| **Cross-framework ambiguity** | 3 / 13 | Generic questions (e.g. "How do I create an agent?", "How do I give an agent access to tools?") retrieve chunks from multiple frameworks (CrewAI, LangChain, LangGraph) at once, and the generated answer blends them together instead of asking which framework the user means. |

### Known Limitations

- No automated scoring (exact-match / semantic similarity against a gold answer set) — evaluation is manual review only.
- The retriever doesn't disambiguate framework-generic questions, leading to blended, cross-framework answers.
- The LLM occasionally states a plausible-sounding but incorrect technical detail (e.g. a config format) even when its citations are accurate — a known faithfulness gap in local, smaller models like `llama3.1` compared to larger hosted models.
- Retrieval quality depends on document freshness at the time `build_corpus.py` was run — if the upstream doc repos change their file paths, some pages may fail to fetch (the script logs any missing/skipped pages).
